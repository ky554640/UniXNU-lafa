# 首次上机记录：UEFI 固件在真机启动成功

日期：2026-11-01
设备：realme GT8 Pro（RMX5200 / RE6030L1 / CANOE），序列号 3B15AW0145P00000
系统：Android 16 / `BP2A.250605.015` / `B.5db4d73`
bootloader：`unlocked: yes`（`verifiedbootstate=orange`，`flash.locked=0`）

## 做了什么

只执行了一条命令，**没有写入任何分区**：

```bash
fastboot boot out/lafa/boot.img
```

镜像内容 = `gzip(BootShim + SILICIUM_UEFI.fd) + 原厂 vendor_boot 的 14 个 DT 集合`，
Android boot header v4，无 ramdisk，无 cmdline。

fastboot 侧输出：

```
Sending 'boot.img' (8696 KB)                       OKAY [  0.188s]
Booting                                            OKAY [  0.249s]
Finished. Total time: 0.443s
```

## 屏幕上发生了什么

固件起来了，屏幕上显示出 EFI 界面；因为没有 payload，UniXNU 提示"没有系统"，然后主动复位。

约 40 秒后设备重新出现在 adb 中。`/proc/uptime` = 18 秒，`ro.boot.bootreason` = `bootloader`
（bootloader 主动重启，不是内核 panic）。扣掉 Android 冷启动的 25~35 秒，镜像实际运行了 5~10 秒。

## 这一步验证了什么

一次通过，没有反复：

| 环节 | 结论 |
|---|---|
| OEM ABL 接受镜像格式 | ✅ 接受带 DT 集合的 header v4 镜像 |
| BootShim 跳转 | ✅ 成功把控制权交给 FD |
| UEFI DXE 初始化 | ✅ 走完并进入 BDS |
| 内存映射 | ✅ `MemoryMapLib` 的 lafa 版可用（含按 DT 补的 7 块保留区）|
| **显示** | ✅ **GOP 上屏成功**，1440×3136 的分辨率推断正确 |
| UniXNU 应用 | ✅ 启动并走到"无 payload"分支 |
| 缺什么 | payload（内核 kernelcache + 信任缓存 + 数据 ramdisk）|

显示这一关原本被评估为最大卡点（BOE AE084 + Pixelworks IRIS7P 独立显示芯片），
结果是**不需要面板驱动**：`SimpleFbDxe` 直接用 ABL 预留的 `Display_Reserved`
carveout 作为帧缓冲，绕过了 DSI/IRIS 整条链路。这是 UEFI 路线相对内核显示方案的核心优势。

## 为什么拔掉 payload 也能验证

`--ramdisk none` 时镜像里没有 FAT 卷，`UniXNURamDiskDxe` 无内容，
UniXNU 找不到可引导系统 —— 但它已经把 UEFI 该做的事全做完了。
换句话说，"提示没有系统"本身就是成功信号：能提示，说明前面全通了。

## 恢复方式

任何情况下长按电源键 10 秒强制重启，即回到原 Android 系统。
`fastboot boot` 不触碰 boot / vendor_boot / vbmeta，断电即失效。
