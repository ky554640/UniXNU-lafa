# lafa 触控 S3910 驱动移植对照表

> 目标：把 data-a-live（pandora 小米 17 Pro）已跑通的 `pandora_touch.c`（Synaptics S3910P TouchComm over SPI）移植到 lafa（realme GT8 Pro，SM8850）。
>
> 结论：**触控硬件接线 99% 相同，只需改 4 处板级参数 + 面板分辨率**。核心的 SPI/GENI/GPI/SMMU/TouchComm 协议全部复用。

## 一、关键结论：硬件接线几乎完全一致

lafa 的触控节点（`lafa_dtbo_0.dts` fragment@24，`synaptics_tcm_hbp@0`）与 pandora 的实际接线对比：

| 硬件项 | pandora | lafa | 是否一致 |
|---|---|---|---|
| 触控 IC | Synaptics S3910P | Synaptics S3910 | ✅ 同一系列 |
| SPI 总线 | QUPv3 SE19 @ `0x1a80000` | QUPv3 SE19 @ `0x1a80000` | ✅ 完全一致 |
| SPI 引脚 | GPIO 48 MISO / 49 MOSI / 50 CLK / 51 CS | 同左（qup4_se0_l0~l3） | ✅ 完全一致 |
| SPI 频率 | 9.6 MHz（XO/2） | 19 MHz（`spi-max-frequency=0x121eac0`） | ⚠️ 上限不同（见下） |
| IRQ | GPIO 158 (0x9e)，低电平 | GPIO 158 (0x9e)，低电平 | ✅ 完全一致 |
| RESET | GPIO 66 | **GPIO 159 (0x9f)** | ❌ 需改 |
| AVDD | GPIO 117 | **GPIO 66 (0x42)** | ❌ 需改 |
| iovdd (RPMh) | LDO "L4I_E0" | LDO **"L4B"** | ❌ 需改 |
| GENI SE 寄存器 | SE0 @ 0x1a80000 | SE0 @ 0x1a80000 | ✅ 完全一致 |
| GPI DMA | GPII 1 @ 0x1a00000-0x10000+... | 同左（wrapper 4） | ✅ 完全一致 |
| SMMU | 0x15000000，stream 0x536/0x523 | 同左 | ✅ 完全一致 |
| 面板分辨率 | 1220×2656（呈现 1125×2436） | **1440×3136（呈现同）** | ❌ 需改 |

**决定性结论**：SPI 传输、时钟树（GCC wrapper 4 vote 0x52018）、GENI SE、GPI DMA、SMMU 流匹配**全部字节级一致**，因为两者都是 SM8850 的 QUPv3 wrapper 4 SE0。唯一的板级差异是 3 个 GPIO 和 1 个 RPMh LDO 名，加上面板分辨率。

## 二、HBP 封装说明（重要）

lafa 的 DT 里触控兼容字符串是 `synaptics,tcm-spi-hbp`（而非 pandora 的 `synaptics,tcm` 标准 TCM），且挂着 `oplus,hbp_spi_bus`（`oplus,hbp_core`）。

- **HBP（Host Bus Protocol）是什么**：OPPO/realme 在标准 SPI 之上加的一层**软件封装**，用于在 Linux 侧统一不同触控 IC 的数据通路（透传、固件下载、report 分发）。它跑在 `hbp_spi_bus` 这个虚拟 SPI 主控上。
- **对移植的影响**：**无影响**。因为 HBP 是纯软件层，触控 IC 本身仍然说原生 Synaptics TouchComm 协议。`pandora_touch.c` 是直接和 IC 的 TouchComm 帧对话（绕过 Linux 的 HBP 封装），这正是 bare-metal XNU 环境需要的正确做法。
- 换句话说：**不需要移植 HBP 框架**，只需要保证 SPI 物理传输正确、然后说 TouchComm 即可。

## 三、已应用的 4 处修改（lafa_touch.c）

| # | 位置 | pandora 原值 | lafa 新值 | 说明 |
|---|---|---|---|---|
| 1 | `#define PT_RESET` | 66u | **159u** | 复位 GPIO 0x9f |
| 2 | `#define PT_AVDD` | 117u | **66u** | AVDD 使能 GPIO 0x42 |
| 3 | `rh_lookup("L4I_E0", ...)` | L4I_E0 | **"L4B"** | iovdd 1.8V LDO 名 |
| 4 | 面板分辨率（3 处） | 1220×2656 / 1125×2436 | **1440×3136**（无缩放） | lafa 面板与显示同分辨率 |

另有：品牌宏 `PANDORA`→`LAFA`、函数 `pandora_touch_init`→`lafa_touch_init`、启动参数 `pandora_touch`→`lafa_touch`（含 `lafa_thp_*`、`lafa_steps`、`lafa_touchdelay`）、日志前缀 `PANDORA TOUCH`→`LAFA TOUCH`。

## 四、无需修改的通用部分（已验证复用）

以下代码块从 pandora 原样保留，因为 SM8850 平台通用：

1. **GCC 时钟投票**：`pt_clocks()` —— GCC_VOTE 0x52018 bits 22-26、SE0 RCG 0xa9014，SM8850 全平台一致。
2. **GENI SE 初始化**：`pt_se_init()` —— SE0 固件 SPI 模式、FIFO 接口禁用、GPI DMA 模式。
3. **GPI DMA 引擎**：`pt_gpi_init()`、`pt_tre()`、`pt_gpi_wait()` —— wrapper 4 GPII 1、TX/RX 通道、事件环。
4. **SMMU 流匹配**：`pt_smmu_setup()` —— stream 0x536（GPI）/ 0x523（QUP），复制 UFS stream 0x60 的 S2CR。
5. **RPMh 投票**：`pt_rpmh_vote()` —— apps RSC DRV 2、ACTIVE TCS、cmd-db 查找（仅资源名从 L4I_E0 改为 L4B）。
6. **TouchComm 协议**：`tc1_*`/`tc2_*`（v1/v2 检测）、`tc_detect()`、`tc_setup()`、`tc_touch_report()` —— Synaptics S3910 通用。
7. **THP 帧解析**：`tc_thp_frame()` —— 16×35 电容矩阵找手指（仅分辨率换算改 1440×3136）。

## 五、SPI 频率差异说明

| 项 | pandora | lafa |
|---|---|---|
| 驱动分频 | `PT_SPI_DIV = 2` → 19.2/2 = **9.6 MHz** | 同（复用） |
| DT 上限 | （未说明） | `spi-max-frequency = 0x121eac0` = **19 MHz** |

lafa 的 DT 声明了最高 19 MHz，但 pandora 的驱动用 XO/2 = 9.6 MHz（低于上限），这是**保守且安全**的选择，直接复用即可。如果需要更高吞吐可以后续调 `PT_SPI_DIV=1`（19.2 MHz），但 9.6 MHz 对触控报点率（60 Hz）完全够用。

## 六、分级测试步骤

与 GPU 一样，触控也建议分级点亮，避免总线挂死：

| 级别 | 启动参数 | 验证内容 | 预期结果 |
|---|---|---|---|
| 1 | `lafa_touch=1` | 只 probe：GCC 时钟、SE、引脚状态 | 日志打印 GCC vote / SE 状态 / 引脚，**不碰 SPI** |
| 2 | `lafa_touch=3` | + RPMh 投 L4B 1.8V | 日志打印 "L4B 1800 mV vote ... done=1" |
| 3 | `lafa_touch=7` | + SPI 初始化 + reset + TouchComm identify | 日志打印 identify 信息（part、build、max 读写） |
| 4 | `lafa_touch=0xf`（默认） | + 触摸上报 | 日志打印 touch reports，触屏可点 |

**辅助参数**：
- `lafa_steps=MS`：每次访问新寄存器区域前打印名称并等待 MS 毫秒，用于定位总线挂死点。
- `lafa_thp_thr=200`：THP 帧手指阈值；`lafa_thp_swap=1`：35 行×16 列读法；`lafa_thp_flip`：位 0/位 1 镜像 x/y。

## 七、风险与注意事项

1. **AVDD GPIO 66 的极性**：lafa DT 里 `synaptics,avdd-gpio = <0x42 0x09 0x01>`，第三个值 0x01 是 active-low 标志。但这里 0x42 是 gpio-regulator 的 phandle（不是 TLMM 直连），驱动里 `pt_gpio(PT_AVDD, 0, 0, 2, 1)` 输出高电平。**需要实测确认**：如果 AVDD 实际是低有效，要把最后的 `1` 改成 `0`。这是触控移植唯一的不确定点。
2. **RPMh L4B 资源名**：从 dtbo 的 `L4B = "...synaptics_tcm_hbp@0:vdd-supply:0"` 推断，但 cmd-db 里的精确 VRM 资源名（如 "L4B" vs "pmh0101.l4b"）需要实测。`pt_rpmh_vote()` 会用 `rh_lookup("L4B", ...)` 在 cmd-db 里查找，找不到会打印 "no VRM match" 并跳过（不会挂死，但触控可能因缺 1.8V 无法工作）。
3. **总线挂死风险**：与 GPU 相同，cfg_ahb 关时读 GCC、SE 未上电时访问寄存器会挂死整机。务必用 `lafa_steps` 分级定位。
4. **面板坐标映射**：lafa 触控 IC 上报的 max_x/max_y 会在 app info 里动态读到，驱动按 1440×3136 换算。如果 touch 位置镜像/旋转（因为 lafa 是打孔屏 + 特定装配方向），可能需要调 `lafa_thp_flip` 或检查 IC 的实际坐标系。

## 八、编译集成

与 GPU 相同，触控驱动注册进内核源码树：

1. `lafa_touch.c` 写入 `bsd/dev/`
2. `bsd/conf/files` 加一行：`bsd/dev/lafa_touch.c  standard`
3. 在 `bsd/dev/sweet_ufs.c` 里 `extern void lafa_touch_init(void);` + 在 `sweet_ufs_init` 里调用 `lafa_touch_init()`
4. 编译时定义 `LAFA` 宏（`-DLAFA`）

依赖：`sweet_hid_touch()`（SweetHIDTouch，pandora 补丁里已有）、`sweet_fb_display_off`（SweetFramebuffer）。
